# 符文档案 · 周报

Riftbound(符文战场)城市挑战赛赛事数据的纯前端分析工具,按期发行的奥术档案周刊。上传赛事数据包,即刻获得**真实胜率驱动的 Tier 分级、传奇域对分布、万金油单卡、Combo 羁绊、地域地图与带卡图的卡组浏览器**的完整 Meta 洞察。

- **期刊与全部分析工具无需后端、无数据库**:构建产物本地双击即可使用(卡图需联网加载,离线自动降级为文字色块)
- **内置隐藏的内容后台「编辑部」**(见下文):校勘卡表 / 规则书 / 资源并发布,需 Supabase 连接与管理员登录,且需 http(s) 环境
- **默认部署目标**:Cloudflare Pages
- 技术栈:Vite + Vue 3 + TypeScript + ECharts + Tailwind CSS(编辑部同样只用这些,不引入组件库)

## 数据准备

**卡表(cards_base × card_prints)已内置预加载**——随站点发布的静态数据,含全量卡牌元数据与 CDN 卡图索引,无需上传;启动后自动就绪(file:// 直开等离线场景可在导入页手动上传兜底)。

在「数据导入」页上传以下赛事文件(**第 1 个必需**,后 2 个可选但强烈推荐;点任意上传框可一次多选,按文件名关键词自动识别槽位):

### 必需(赛事数据)

| 槽位 | 文件 | 说明 |
|---|---|---|
| 📊 赛事卡组 | `*decks_data*.csv` | 列:`activityName` / `shopProvince` / `date` / `finalRanking` / `playerName` / `hero` / `TTS_code` |

### 可选(增强能力)

| 槽位 | 文件 | 解锁 |
|---|---|---|
| 🏅 名次胜场 | `*rank_data*.json` | **真实胜率**(瑞士轮胜场/轮次)、按胜场排序、城市×英雄胜率热力、Tier 以胜率为核心 |
| 🏪 赛事门店 | `*shop_data*.json` | **精确城市/门店/赛事规模**,替代正则猜城(实测 24/24 场全命中) |

> 卡图索引直接来自内置 `card_prints`;卡图缺失时自动降级为文字色块。
> 轮次推断:每场赛事总轮次 = 该场 `winCount` 最大值(128 人 → 7 轮瑞士轮,已验证)。
> 胜率 = Σ胜场 / Σ轮次,为加权口径。

### 全局联动

- 顶部范围条:**周次选择**(数据包可含一周或多周,默认聚焦最新一周;「全部周」为汇总口径),实时显示样本数;趋势对比页始终跨全量数据计算,不受周次筛选影响
- 图表点击下钻:总览散点/Tier 行点英雄 → 英雄拆解定位该英雄
- Tier 综合分 = 胜率分位×0.55 + Top8率分位×0.20 + 出场率分位×0.25(S ≥ p85 / A ≥ p60 / B ≥ p30);样本 <15 或无胜率数据不评级
- 总览头条「最佳传奇」按**转化综合分**选取:Top8 率×60% + 冠军率(rank=1)×40%,不使用胜率
- 卡牌统计口径:符文卡与传奇卡(结构性卡牌)不计入携带率分析;卡图优先采用简体中文(SC)印刷版本
- 浅色/深色/跟随系统三档主题,图表即时重绘

## 编辑部(后台)

站点内置一个**隐藏的内容后台**,用于校勘与发布卡表、规则书与资源。它不在导航里。

**进入方式**:连点报头刊名「符文档案·周报」**5 次**(相邻两次间隔不超过 3 秒),
「编辑部」便会出现在栏目导航中。第 2 次起刊名下方会浮现一条朱砂细线作为进度反馈。
解锁状态存在本机浏览器,刷新不丢。

进入后仍需**管理员登录**(Supabase Auth,角色存于 `app_metadata.role`)。

| 工具 | 路由 | 作用 |
|---|---|---|
| 总览 | `#/editorial` | 5 个工具的入口 |
| 卡牌校勘 | `#/editorial/cards` | 单卡全字段 + 印刷版本子表 + 转移绑定 |
| 批量校勘 | `#/editorial/batch` | 内联编辑、批量禁限/数值 ±N/改系列、差异预览 |
| 规则校勘 | `#/editorial/rules` | 规则书树形编辑 + 子串检索 + 防环 |
| 资源与发布 | `#/editorial/resources` | 系列 CRUD、图标库、版本发布标记 |
| 数据同步 | `#/editorial/sync` | 官方接口拉取 → 逐条编辑／勾选字段 → 分阶段提交／SQL／CSV |

### 关于「发布」

库中**没有触发器**,`updated_at` 不会自动刷新。客户端靠 `version` 表的时间戳判断缓存失效,
因此**任何数据改动都必须显式触碰对应分类**,否则前端不会感知到更新 ——
各校勘页的「保存并发布」按钮做的就是这件事。

### 站点卡表快照闭环

「数据同步」页可一键导出 `public/data/cards_base_rows.csv` 与 `card_prints_rows.csv`
(站点预加载用的卡表),并在下载前自检格式(**数组列 JSON 编码 · 无 BOM · LF**),
不符则拒绝下载。此前这两份文件只能手工从 Supabase 导出。

### 数据安全

- 前端只用 anon / publishable key,`service_role` 绝不出现在浏览器端
- 所有写操作经服务端行级安全策略(`is_card_admin`)校验,前端不做权限判定的最终依据
- 数据同步**只写接口拥有的列**;人工维护列(`keyword` / `advanced_tag` / `deck_limit` / `*_en` /
  `tts_cdn` 等)、`back_image` 与 `is_banned` 不参与同步；已有基础卡仅更新勘误效果。
- 单条、批量与导出共用字段审核规则，详见 [同步审核说明](docs/sync-review.md)

## 开发与部署

```bash
npm install
npm run dev        # 本地开发
npm run build      # 类型检查 + 构建到 dist/
npm run preview    # 预览构建产物

npm run verify:all # 全部验证:类型检查与各项回归验证
```

编辑部需要 `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY`(见 `.env.example`);
缺失时编辑部显示配置说明页,**期刊与本地分析工具完全不受影响**。

Cloudflare Pages 配置:框架预设 None,构建命令 `npm run build`,输出目录 `dist`。
仓库根目录的 `functions/` 会同时部署 QA 同源转发函数，用于解决官方
`cardCommonQa` 端点不返回 CORS 头的问题。本地 `npm run dev` / `npm run preview`
由 Vite 将同一路径代理到官方接口。

数据仅供竞技参考 · Riot Games 与本工具无关。
