**建议的整体方案**

在现有 Vue 3 项目内实现独立的构筑模块，复用现有卡牌查询、卡图、筛选、缓存与管理员认证。参考项目的 Svelte 页面和 Tauri 数据库操作转换为适合浏览器的 Vue 组件与存储适配层。

页面拟分为「我的卡组」「构筑工作台」「分享卡组」三个状态，路由暂定：

| 页面 | 拟定路由 | 主要作用 |
| --- | --- | --- |
| 我的卡组 | `#/builder` | 浏览本机卡组；管理员查看自己的云端卡组 |
| 构筑工作台 | `#/builder/edit/{id}` | 新建、恢复草稿、编辑卡组 |
| 分享卡组 | `#/builder/share?s=…` | 无需登录查看固定快照，复制为新卡组 |

路由参数和名称为实现建议，最终接入需扩展当前 hash 路由对构筑子页面的解析。新增工具不要求先载入赛事数据包。首页第四个主入口显示「卡组构筑」，进入「我的卡组」，提供醒目的「新建卡组」和「导入卡组」。

**文字描绘：我的卡组**

页面沿浏览器可用宽度展开。左上角是衬线标题「我的卡组」，右侧是「新建卡组」「导入卡组」。下一行放搜索框和最近修改排序，搜索卡组名称或传奇名称。

主体为随屏幕宽度增加列数的卡组网格。每套卡组用主传奇的卡图裁切作为识别图，下面显示卡组名称、最近保存时间和各分区数量摘要。状态用短文字表示「已保存」「有草稿」「构筑有问题」。点击卡组进入编辑，右上角菜单提供重命名、复制、分享和删除。

普通访客看到本机卡组。管理员登录后，标题下方出现「本机」「云端」切换；云端库展示当前账号自己的卡组。建议以显式「保存到云端」「另存到本机」处理两种存储之间的转移。

空库显示「创建第一套卡组」，旁边保留导入入口。已有草稿时，库中对应卡组显示「继续草稿」，用户可以恢复，也可以选择正式保存的构筑。

**构筑交互与规则提示**

1. 新建后先选择分区。选择传奇后可自动切换到英雄，选择英雄后切换到主牌，沿用参考项目的连贯流程。
2. 卡池依选定分区显示相应类型；主传奇颜色与英雄条件作为默认推荐筛选，并有清晰的「显示全部」入口，便于实验构筑。
3. 点击卡池卡图加入当前分区；每张卡另有可触达的详情入口，查看效果与卡图。
4. 卡组条目提供数量加减、切换印版、移动和移除。主牌与备牌之间用菜单移动。加减与移动均进入本机草稿。
5. 同一基础卡的不同印版分别保留，文字／卡图视图均显示数量。按后续确认，构筑卡池及印版选择仅提供 SC 简中印卡；显示卡图和版本信息。已有或导入的非 SC 条目保留，不静默替换或删除，用户可手动换成可用 SC 印版。
6. 主牌堆的英雄单位、专属单位归入「单位」，专属法术归入「法术」，专属装备归入「装备」。导入的异常类型保留并单列问题，避免卡牌隐藏或丢失。
7. 张数不足、超限、禁卡、同名数量、分区类型、颜色条件等作为规则问题展示。保存和分享允许继续；数据结构错误、无法识别的格式等需要先解决，区别于允许保留的游戏规则问题。
8. 更换传奇后保留已选卡牌，重新计算推荐筛选及构筑问题。

统计建议默认以英雄加主牌的 40 张主牌堆为口径：费用曲线、颜色分布、单位／法术／装备数量。备牌可作为单独统计或勾选纳入，额外传奇不影响主牌数量与费用曲线。多色卡的颜色计数需要明确口径。

**妮蔻与额外传奇**

触发检测遍历卡组所有分区，包括额外传奇中已有的卡牌。按卡牌身份识别妮蔻，首期采用名称／英雄标识白名单；匹配卡牌名和身份字段，避免将效果文字中提及妮蔻的其他卡牌当成触发卡。

任意位置出现妮蔻时，分区选择器增加「额外传奇」，卡池显示传奇类型。卡组侧显示该分区和 `已选数量/3`。额外传奇的选择不受主传奇颜色限制，同名判定跨主传奇与额外传奇，印刷版本差异不改变同名关系。

正常操作推荐互不重名的传奇。超出 3 张、与主传奇或额外传奇重名时，列入规则问题，仍按实验构筑策略保存。导入的数据完整保留。

最后一张妮蔻移除后，已有额外传奇保留在卡组中，分区标记「需要妮蔻」，支持查看与移除。重新加入妮蔻后恢复正常。无妮蔻且无额外传奇内容时，隐藏该额外区域。

额外传奇作为独立分区保存，参与草稿、云端数据、分享链接、图片、文字与代码适配，不占用主传奇名额，也不计入主牌 39 张。

当前站点随包静态卡表共有 971 条基础卡记录，本次读取未找到妮蔻记录。因此构筑卡池需复用当前公开卡牌查询的更新数据与缓存，静态快照作为回退来源。妮蔻身份配置在实现时结合实际可用卡表落定；本次尚未查询实际云端卡表。

**保存流程**

本机存储建议沿用当前工具的浏览器持久化方式，分别保存正式卡组、草稿与界面偏好。仅存储卡组所需的卡号、印版、语言、数量和分区等紧凑信息，卡牌资料与图片沿用共享缓存。

点击「保存」更新当前正式构筑。每次编辑自动保留本机草稿，界面显示「草稿已保留，正式构筑未更新」。刷新或重进时可以继续草稿。正式保存成功后清理或对齐对应草稿。草稿写入失败时提供就地状态反馈；未写入的数据不显示已保存。

首次保存填写卡组名称，备注建议作为可选字段。已有卡组可通过名称编辑完成重命名。复制生成独立卡组标识，后续保存互不覆盖。

管理员登录后显示云端库和保存到云端的操作。建议：编辑本机卡组时默认保存本机，可另存到云端；编辑云端卡组时主按钮显示「保存到云端」，另存本机作为菜单操作。云端草稿按账号隔离。

云端保存采用当前管理员认证和 REST 通道，读写都携带当前用户身份。每条云端卡组同时受管理员角色与所有者限制，服务端按账号隔离。账户切换、登出和登录失效后，云端页面及缓存按相应身份处理。

建议使用独立的网页卡组表，完整构筑作为一份结构化文档存储；所有者、名称和修改时间为可查询字段。保存时检查云端修改标识，避免不同设备的旧页面静默覆盖新内容；冲突提供重新载入或保存为新卡组的处理方式。此修改标识用于并发保存，不是历史卡组版本。

**分享与导入的 UI**

点击「分享」打开操作面板，提供「链接」「图片」「TTS 码」「卡组代码」「文字」五个标签，对应用户确认的四类分享方式。分享默认针对工作台当前构筑，并标明「包含未保存修改」等状态；用户可先查看预览。

| 方式 | 建议呈现与数据处理 |
| --- | --- |
| 链接 | 复制固定构筑快照；冻结卡组名称、备注、分区、选牌、印版、语言与数量；卡牌效果按站点当前卡表显示 |
| 图片 | 预览后下载；卡组名称、主传奇／英雄、分区、数量、主牌类型分组、额外传奇和问题状态都出现在图片中 |
| TTS 码 | 沿用现有 TTS 卡号与顺序约定生成；显示兼容性与缺失印版信息 |
| 卡组代码 | 使用支持额外传奇字段的编码方式；按代码格式能表达的信息导出 |
| 文字 | 提供带分区、编号、数量的清单；本站完整格式同时保留印版、语言与额外传奇 |

分享链接建议在 hash 查询中携带压缩后的构筑快照，无需为访客开通云端卡组写权限。接收者看到只读卡组页，顶部有「复制到我的卡组」。复制后创建独立草稿，手动保存后进入接收者的本机库。

图片布局针对群聊阅读：保留所选卡图和明显数量标签，按分区和主牌类型排版。若卡图不可用，保留卡名、编号与数量占位，确保完整卡表仍可读。图片内容来自同一份构筑模型。

导入窗口提供输入区并识别 TTS 码、卡组代码和文字。解析后先展示分区预览、张数、印版和问题；未知编号、歧义卡名等保留为待处理条目，用户可补配或移除。确认导入后创建新草稿。

现有 TTS 码与通用卡组代码不能表达本站全部编辑状态。TTS 码以顺序推断分区；未完成构筑、超限构筑和额外传奇的分区需要预览、调整。通用代码不携带印刷语言等全部信息。链接与本站完整文字作为保留全部构筑信息的分享方式，各格式导入均明确展示解析结果。

对于 TTS 中不明确的额外传奇分区，导入预览提供专门归区操作；导出保证显示包含的完整卡牌清单，实际目标 TTS 工具对额外传奇的生成方式需在实现阶段验证。构筑内容与格式兼容性分别反馈，避免静默跳过卡牌。

从赛事卡组复制的入口拟放在现有卡组详情抽屉的操作区，显示「复制到构筑」。复制后生成独立草稿，并保留赛事／选手等来源备注。后续编辑作用于该新卡组。赛事里缺失的数据在导入预览中显式展示。
